# Политика безопасности

> English version: [SECURITY.md](SECURITY.md)

## ⚠️ Прочтите сначала: учебный код, не продакшн-код

**basicthon — учебный репозиторий. Несколько проектов реализуют
security-значимую функциональность как сознательно упрощённые учебные версии.
Ни один из них не безопасен для реального использования.**

Самые важные случаи, по убыванию риска:

| Проект | Как выглядит | Почему нельзя использовать по-настоящему |
|---|---|---|
| **12 — Secret Manager** | Настоящее шифрование Fernet (AES + HMAC) | Нет ротации ключей, нет жёстких прав на файлы, нет защиты памяти, единый JSON-индекс с незашифрованными именами, нет атомарной записи. Игрушечный сейв. |
| **17 — FastAPI JWT** | Рабочий флоу login/register/`Bearer` | In-memory хранилище пользователей (стирается при рестарте), жёстко прописанный dev-ключ (`dev-secret-key-change-me`) если `$SECRET_KEY` не задан, нет refresh/отзыва токенов, нет принудительного HTTPS, нет rate limiting. |
| **16 / 20 — REST API** | Чистая семантика CRUD | Нет аутентификации ни на одном эндпоинте; любой, кто достучался до порта, может читать и удалять все данные. |
| **18 — Telegram-бот / 19 — Ollama-чатбот** | Паттерны работы с токенами/env | Демонстрируют правильные *привычки* (секреты через env, никогда не логируются), но собственной threat model за пределами этого не имеют. |

Это не случайность и не недосмотр: ARCHITECTURE.md §9 фиксирует это как цель
дизайна («№12 — учебная реализация с явной пометкой "не для реального
использования"»). Упрощения существуют, чтобы каждая концепция помещалась в
модуль, читаемый новичком. Каждый затронутый проект повторяет это
предупреждение в своём README.

**Не храните реальные пароли, API-ключи, токены или персональные данные ни в
одном проекте этого репозитория.**

## Сообщение об уязвимости

Нашли что-то сломанное в учебном коде? Сообщения приветствуются.

- Для всего, что может подтолкнуть учащегося к небезопасной привычке
  (например, крипто-ошибка, *не* покрытая задокументированными упрощениями
  выше), откройте GitHub issue с описанием проекта, файла и риска.
- Для действительно чувствительных находок, которые вы не хотите публиковать,
  свяжитесь с мейнтейнером напрямую через GitHub.
- Пожалуйста, укажите: номер/имя проекта, затронутые файлы, шаги
  воспроизведения и какая из задокументированных упрощений (если есть) это
  уже покрывает.

Сообщения, противоречащие задокументированной области выше (например,
«проект 12 не ротирует ключи» или «проект 17 без rate limiting»), будут
закрыты как working-as-documented — но если вы считаете, что само
задокументированное решение неверно, issue против [ARCHITECTURE.md](ARCHITECTURE.md)
§9 очень приветствуется.

## Политика секретов для контрибьюторов

- Файлы `.env.example` содержат **только плейсхолдеры и подсказки по
  генерации** (`change-me-to-a-long-random-secret-32-bytes`,
  `1234567890:AA-your-token-here`). Никогда не коммитьте файл `.env`,
  заполненный токен или какие-либо креденшеллы где-либо в этом репозитории.
- Тесты никогда не используют реальные ключи, настоящих ботов или сетевой
  доступ; они мокают HTTP и используют временные каталоги
  (ARCHITECTURE.md §5, правило G-12).
- Если случайно закоммитили секрет: немедленно отзовите/замените его на
  стороне провайдера до чистки истории — удаление из git не «распечатывает»
  уже утёкшее.

## Область действия

Внутри области: всё в учебном коде, что противоречит собственной документации,
обучает небезопасному паттерну без предупреждения или раскрывает закоммиченные
креденшеллы.

Вне области: сознательные упрощения из таблицы выше; слабые пользовательские
вводы в демо-флоу; отсутствие продакшн-фич (ротация, rate limiting, HTTPS),
от которых каждый README явно отговаривается.

## Поддерживаемые версии

Исправления получает только актуальное состояние `main`. Release-веток нет.

# ARCHITECTURE — 20 Финальная интеграция

> Требуется по ARCHITECTURE.md §6 (≥2 решения) — здесь явное решение схемы БД плюс сквозное интеграционное решение (три двери к одному хранилищу); файл включён, так как это выпускной проект, объединяющий паттерны 04/11/16.

## 1. Решения

### 1.1 Схема БД — одна таблица `tasks` в SQLite (адаптировано из №11)

**Выбрано:** таблица `tasks(id INTEGER PRIMARY KEY AUTOINCREMENT, title TEXT NOT NULL, completed INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP)` через `sqlite3` с параметризованными запросами. Маппинг строки → dataclass. `completed` хранится как INTEGER 0/1 и конвертируется `bool(int(...))`.

**Почему SQLite:** stdlib, один файл, без сервера — соответствует изоляции репозитория. Идемпотентное создание таблицы позволяет CLI и API оба вызывать `create_db()`. Короткоживущие соединения на операцию достаточны для однопользовательской игрушки.

**Отклонено:** JSON-файл (нет безопасности при параллельном чтении), SQLAlchemy (прячет SQL), Postgres (нужен сервер), несколько таблиц (уводит фокус с интеграции).

### 1.2 Форма интеграции — три слоя над одним хранилищем (CLI из №04, API из №16)

**Выбрано:** `storage.py` держит весь SQL и валидацию; `api.py` оборачивает функции в роуты FastAPI с Pydantic-моделями; `cli.py` даёт подкоманды (`add/list/get/done/delete/serve`) поверх того же SQLite-файла.

**Почему так:** правила (strip/длина title) живут один раз в `storage.py`; строка, добавленная через CLI, видна через `GET /tasks` без синхронизации — это демонстрирует тест `test_cli_and_api_share_db`. Границы наглядны: никаких импортов fastapi в storage, никаких SQL-строк в api/cli.

**Отклонено:** CLI через HTTP (требует запущенный сервер), логика в роутах (дублирование), очередь между CLI и API (раздувание объёма).

### 1.3 Конфигурация — только env

**Выбрано:** `DATABASE_PATH` (дефолт `./tasks.db`), `HOST` (`127.0.0.1`), `PORT` (`8000`) через env-хелперы, документированы в `.env.example`. Секретов в проекте нет, но `.env.example` присутствует по GRILL2-06 для единообразия привычки.

## 2. Границы модулей

- `storage.py` — только stdlib: Task, CRUD, get_db_path.
- `api.py` — FastAPI: health + пять роутов задач, две маленькие Pydantic-модели, get_host/get_port.
- `cli.py` — argparse, печать, коды выхода, serve → uvicorn (исключён из покрытия по G-13).
- `__init__.py` — реэкспорт; `__main__.py` — `python -m final_integration`.

## 3. Почему не для продакшена (§9)

Учебный выпускной проект:

1. Нет миграций схемы.
2. Нет аутентификации на API.
3. Соединение на каждый вызов — без пула и WAL.
4. Дублирование-снепшот из 04/11/16 будет дрейфовать (осознанный trade-off изоляции).
5. TestClient покрывает роутинг, но не деплой (прокси, таймауты).

## 4. Модель ошибок

- `ValueError` в storage (title/task_id) → 422 в роутах.
- Отсутствие строк → False/None → 404 в API.
- DELETE возвращает 204 с явно пустым Response — HTTP запрещает тело для 204 (урок из №16).
- `RuntimeError` — только защитные ветки «не должно случиться».

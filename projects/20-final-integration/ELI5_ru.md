# ELI5 — Финальная интеграция (CLI + SQLite + API)

Представь одну тетрадку (файл `tasks.db`) и **три двери** в неё:

- Дверь 1 — **терминал**: `final-integration add`, `list`, `done 1` — печатаешь, строки меняются.
- Дверь 2 — **веб-API**: `POST /tasks`, `GET /tasks` — программы говорят с той же тетрадкой по HTTP.
- Дверь 3 — твой собственный Python-код: `add_task(db, "привет")`.

Все три двери открывают одну и ту же тетрадку — запиши через одну, загляни через другую: уже там. Весь фокус в одном `storage.py`, который знает правила тетрадки (strip заголовков, никаких пустых задач), а обе двери просто его вызывают.

- Тетрадка ничего не забывает — закрой всё, открой завтра, задачи на месте. Это магия SQLite: целая база данных в одном файле.
- У двери API есть охранник (Pydantic): задача без заголовка разворачивается с `422`. Удаление отвечает `204` — «сделано, сказать нечего».
- Этот проект сознательно не придумал ничего нового: часть CLI пришла из проекта №04, база из №11, веб из №16 — скопированы и склеены, чтобы показать: каждый прежний навык был кусочком пазла.

Правила для ребёнка:

- Заголовок не пустой и не длиннее 100 букв.
- Просишь несуществующую задачу → «not found» (404), а не падение.
- Тесты используют одноразовую тетрадку во временной папке — твои настоящие задачи не трогаются.

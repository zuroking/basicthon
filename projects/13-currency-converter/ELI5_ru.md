# ELI5 — Конвертер валют

Представь пункт обмена:

- У тебя есть адрес пункта (`API_URL`, например `https://api.example.com/latest`) и пропуск (`API_KEY`). Оба в кармане (переменные окружения), не в коде. Берёшь `get_api_url()` / `get_api_key()` — если карман пуст, крик `ValueError`.
- Пункт даёт табло курсов: `fetch_rates("USD")` — показываешь пропуск (`headers={"apikey": key}`) и спрашиваешь "курсы для USD?" (`params={"base": "USD"}`). Пункт отвечает JSON `{"rates": {"EUR": 0.92, "GBP": 0.79}}`. Если закрыт (`status != 200`) или табло испорчено (плохой JSON, нет `rates`), крик `ValueError`.
- `convert(100, "USD", "EUR")` — просишь табло для USD, находишь `EUR = 0.92`, возвращаешь `100 * 0.92 = 92.0`. Те же деньги? `convert(10, "USD", "USD")` возвращает `10.0` без запроса.
- Неизвестная валюта? `convert(10, "USD", "XYZ")` где `XYZ` нет на табло → крик `unsupported currency`.
- Пункт может написать `conversion_rates` вместо `rates` — оба варианта работают. Коды без учёта регистра: `usd`, `UsD` → `USD`.

Правила для ребёнка:

- Код валюты — ровно 3 буквы после обрезки пробелов, `USD`, `eur` → `EUR`; `"US"` или `"123"` → ошибка.
- Сумма — конечное число (`int` или `float`), не `True`, не `nan`/`inf`; `-5` разрешено, но `bool` — нет.
- URL должен начинаться с `http://` или `https://`; пустой ключ/URL → ошибка.
- Тесты используют игрушечный пункт (`unittest.mock.patch("currency_converter.converter.httpx.get")`) — ты сам задаёшь JSON ответа, без сети и реального ключа.
- Это игрушечный обменник. Настоящие добавляют комиссии, кэш, много провайдеров и retry — этот делает один `httpx.get` с `timeout=10.0` и строго валидирует.

# ELI5 — Менеджер секретов

Представь дневник с сейфом:

- У тебя есть волшебный ключ (`SECRET_MANAGER_KEY`, 44 символа). Делается `generate_key()`. Храни его вне дневника — в кармане (переменная окружения).
- Дневник — JSON-файл (`secrets.json`). Внутри карточки: `{"api_token": "gAAAA...=="}`. Значение не открытый текст — оно зашифровано ключом.
- `set_secret("api_token", "s3cr3t", key)` — берёт слово `s3cr3t`, шифрует ключом, кладёт карточку `api_token` в дневник. Если карточка есть — перезаписывает.
- `get_secret("api_token", key)` — находит карточку, расшифровывает тем же ключом, возвращает `s3cr3t`. Неверный ключ → крик `ValueError`. Нет карточки → `None`.
- `delete_secret("api_token")` — вырывает карточку. Ключ не нужен, только имя. Нет карточки → крик.
- `list_secrets()` — читает имена всех карточек по алфавиту, ключ не нужен (имена не секретны, значения — да).

Правила для ребёнка:

- Имя после обрезки пробелов не пустое; значение может быть пустым.
- Ключ — валидный Fernet (44 символа); плохой → `ValueError`.
- Дневник — просто JSON, внутри только зашифрованные токены, не открытый текст.
- Тесты используют временный дневник (`tmp_path / "secrets.json"`) — реальный файл, реальное шифрование, без сети.
- Это игрушечный сейф. Настоящие сейфы прячут ключи в железе, ротируют ключи, защищают память и работают на многих пользователей — этот ничего из этого не делает.

# ELI5 — Погодный CLI с retry

Представь будку с погодой:

- У тебя есть адрес будки (`API_URL`, например `https://api.example.com/weather`) и пропуск (`API_KEY`). Оба в кармане (переменные окружения), не в коде. Берёшь `get_api_url()` / `get_api_key()` — если карман пуст, крик `ValueError`.
- Будка даёт погоду: `fetch_weather("London")` — показываешь пропуск (`headers={"apikey": key}` + `params={"q": "London", "appid": key}`) и спрашиваешь "погода для London?". Будка отвечает JSON `{"name": "London", "main": {"temp": 15.5, "humidity": 72}, "weather": [{"description": "clear sky"}]}`. Если закрыта или табло испорчено (плохой JSON, нет `main`/`weather`), крик `ValueError`.
- Будка может быть занята: статус 429 или 500/502/503/504, или сеть упала (исключение `httpx`). Тогда ждёшь и пробуешь снова: 1-я попытка ждёшь `backoff_factor * 1`, 2-я `*2`, 3-я `*4` (экспонента). При `backoff_factor=0.5` спишь 0.5, 1.0, 2.0. После `max_retries` (по умолчанию 3) сдаёшься. Статус 400/401/404 → без повтора, сразу крик.
- `fetch_weather("London")` возвращает `{"city": "London", "temperature": 15.5, "description": "clear sky", "humidity": 72}`. Город написал `  london  ` → для запроса обрежется до `London`, а имя города берётся из ответа будки. Нет `humidity` в ответе? Вернёшь только 3 ключа.
- Неизвестный город? Будка ответит 404 → крик `request failed with status 404` без повтора.

Правила для ребёнка:

- Город — непустая строка после обрезки, до 100 символов; `""` или `"   "` → ошибка.
- `max_retries` должен быть 1..10, `backoff_factor` конечное >=0 (0 — без ожидания).
- URL должен начинаться с `http://` или `https://`; пустой ключ/URL → ошибка.
- Тесты используют игрушечную будку (`unittest.mock.patch("weather_cli.weather.httpx.get")`) и игрушечные часы (`patch("weather_cli.weather.time.sleep")`) — ты сам задаёшь JSON ответа и проверяешь вызовы сна, без сети и реального ключа.
- Это игрушечная будка. Настоящие сервисы добавляют кэш, лимиты, много провайдеров, иконки и прогнозы — этот делает один `httpx.get` с `timeout=10.0` и строго валидирует, но учит retry.
